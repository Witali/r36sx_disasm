Этот протокол описывает вызов процедур хоста из гостевой программы
Обмен идет через двунаправленный 8-битный порт, инициатором обмена выступает гостевая программа

при отправке запроса от гостевой программы хост может отследить появление новых данных в порту по сигналу синхронизации
Гостевая же программа не получает такой сигнал и должна отслеживать появление новых данных по изменению бита синхронизации
То есть перед отправкой сообщения хосту гостевая программа должна прочитать и сохранить у себя значение порта обмена,
отправить свое сообщение хосту, и после этого проверять с определенной периодичностью изменение бита синхронизации.
Если после определенного времени, скажем 5 секунд от хоста не пришел ответ, то завершаем гостевую программу с сообщением:
"Хост недоступен".

Пусть бит синхронизации будет наиболее значащий бит в порте.

Протокол начинается отправкой команды от гостевой программы к хосту. Для дополнительной синхронизации протокола в слове 
команды устанавливается старший бит как признак команды. Если этот бит сброшен, то это признак передачи данных.

Пример протокола:
Команда ping, определение доступности хоста

Гостевая программа                                        Хост
|                                                            |
| <-  Чтение порта обмена для сохранения бита синхронизации -|
|   (не нужно если бит уже сохранен от предыдущего обмена)   |
|                                                            |
| - Отправка команды PING: 0b10000001                     -> |
|                                                            |
| <- <- <- Циклическое чтение до изменения бита синхр.       |
| <- Бит изменился, значит это ответ, например 0b00000001  - |

Если функции rpc достаточно 7 бит для ответа, она сразу возвращает его в нижних 7-ми битах.

Если функция возвращает ответ фиксированного размера, то разбивает ее на куски по 7-бит,
то есть если нужно вернуть 32-битное число, мы берем 7 бит от младшего 0-го байта числа,
отправляем их с хоста в гостевую программу, далее гостевая программа должна запросить продолжение,
отправив команду CONTINUE, в ответ на эту команду берем старший бит от 0-го байта как младший бит
ответа, еще 6 бит из 1-го байта 32-битного числа, и так далее до полной передачи.

Если функция возвращает ответ неопределенного размера, например строку, то в ответ на первую команду
в 7-ми младших битах возвращает размер ответа в Байтах. То есть размер ограничен 127-ю байтами
Далее гостевая программа запрашивает продолжение командой CONTINUE как и для предыдущего примера
с ответом фиксированного размера.

Передача данных от гостевой программы хосту выглядит похоже, только после отправки команды в порт
гостевая программа отправляет данные с нулевым старшим битом. На каждый отправленный байт хост 
отвечает изменением бита синхронизации.
Для посылки неопределенного размера (ограниченной 127 байтами) первая запись данных в порт после 
отправки команды содержит размер последующих данных в байтах.

Кроме вызываемых функций, необходимы функции управления потоком: RESET, ABORT и END.
RESET полностью сбрасывает состояние хоста в начале сессии обмена.
ABORT прерывает текущую команду.
END сигнализирует окончание сессии.

Команды протокола описаны в одном файле являющемся единым "источником правды" для хоста и гостевой
программы.
